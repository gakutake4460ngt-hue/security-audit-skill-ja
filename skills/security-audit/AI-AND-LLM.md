# AI・LLM・エージェントのハンティング

#### このファイルを使う場面

言語モデルが信頼に関わる判断に関与する場合にこのファイルを使う。対象は、チャットボットやアシスタント、RAG パイプライン、エージェントの永続メモリ、エージェント/ツール呼び出しループ、MCP サーバーとクライアント、信頼できない入力からプロンプトを組み立てるコード、モデル出力を受け取ってそれに基づき動作するコードである。重要なデータフローは *信頼できないコンテンツ → モデルまたはメモリ → ケイパビリティ、権限、またはシンク* である。

`ATTACK-CLASSES.md` の代わりではなく、併用する。トランスポート、アクセス制御、クエリ構築、ファイルシステム利用、出力レンダリングは通常の信頼境界のままである。このファイルはモデル固有の委任レイヤーを扱う。大きな対象は、検索 (retrieval)、メモリ、ツールディスパッチ、MCP、出力処理ごとに分割する。

## 基本規律 (この領域のすべてのエージェントプロンプトに含める)

```
- Prompt injection alone is not a finding. Require a code-level boundary failure: content reaches another principal's context, invokes authority the requester lacks, discloses data they cannot read, or drives a sink they cannot reach directly.
- Model output, memory, tool descriptions, and MCP responses are untrusted inputs. Point to the code that grants authority, trusts output, writes durable state, or feeds a sink.
- A guardrail prompt is not a security boundary. Count only deterministic checks, resource-scoped authorization, isolation, binding, and constrained credentials.
- State the attacker, affected principal, effective execution identity, resource, exact action, authority used, and observable impact. An intentional direct request to use the requester's existing authority is not a delegation defect merely because a model executes it.
- Authorization and action binding are separate controls. Attacker-controlled content that causes an action under an affected principal's valid authority is an action-binding failure when that principal did not intentionally request or approve the exact action.
- Classify every candidate as `confirmed` only after source evidence and bounded local validation establish the boundary and result. Use `needs_validation` when a required provider, deployment, model, renderer, or identity behavior is not observable locally.
```

## コンテキスト・検索・メモリの攻撃クラス (subagent_type: `general`)

**検索・取り込みコンテンツ経由の間接インジェクション**
攻撃者が、RAG ドキュメント、インデックス済みページ、ファイル、メール、issue 本文、ツール応答、メタデータを書き込め、それが別のプリンシパルのモデルコンテキストに入る。各ソースに誰が書き込めるか、検索がそれをどうスコープするか、誰のセッションがそれを消費するか、そこでどのケイパビリティが有効になるかを追跡する。分離、リソース認可、消費側プリンシパルの意図への束縛は個別に確認する。欠陥は決定論的な制御の欠如であり、説得力のあるテキストそのものではない。

**セッション間・テナント間のコンテキスト漏出**
会話履歴、埋め込み、検索結果、プロンプトキャッシュのキーが広すぎる。テナントと ACL のフィルタがクエリ自体とすべてのキャッシュキーに含まれているかを検証する。オブジェクトにテナントフィールドが保存されていても、別のクエリ、共有キャッシュ、バッチ経路がそれを省略するなら強制にはならない。

**永続メモリポイズニング**
攻撃者が制御するコンテンツやモデルの要約がメモリに書き込まれ、後で別のタスク、ユーザー、特権セッションに影響する。誰がメモリを作成・更新・マージ・削除できるか、その出所 (provenance) とテナントスコープ、低信頼の観察結果が永続的な指示や事実になるか、検索がユーザーの好みとツールポリシーを区別するかをレビューする。ユーザーが意図的に保存し、そのユーザー自身の意図的で許可されたリクエストにのみ使われるメモリは、境界を越える指摘ではない。

**プロンプトのロールと出所の混同**
プロンプト組み立てにより、信頼できないテキストがシステムメッセージ、過去のターン、ツール結果、ポリシー、メモリレコードになりすませる。文字列連結、型のない履歴、呼び出し側が制御するロールフィールド、ソースラベルが失われるシリアライズの往復を探す。偽造された出所が決定論的な信頼判断を変えるか、意味のあるケイパビリティに到達することを確認する。

## ツールとアクションの攻撃クラス (subagent_type: `general`)

**下流シンクへのツール引数インジェクション**
モデルが生成した引数が、ハンドラ側の検証なしに SQL、シェル、ファイル、URL 取得、特権 API に到達する。ツールスキーマを入力パースとして扱い、デコードされた呼び出しからシンクまで各フィールドを追う。構造化出力は形を絞り込むが、認可、安全なパス、安全な URL、クエリの意味を保証しない。

**過剰なエージェンシーと confused deputy の権限**
エージェントがサービス ID や広範なクレデンシャルを使い、ツールハンドラが指定リソースに対するリクエスト元プリンシパルの権限を再確認しない。実効 ID と、呼び出し元が通常のプロダクトインターフェースでその操作そのものを行えるかの両方を検証する。ユーザーごとのクエリスコープが強制された共有クレデンシャルは欠陥ではない。

**アクション確認と承認の束縛**
ユーザーが説明された 1 つのアクションを承認するが、実行時に変更された引数、別のリソース、別のプリンシパル、後のモデルターンが使われうる。攻撃者が制御するコンテンツが、被害者の意図的なリクエストや承認なしに被害者の有効な権限で副作用を起こす場合も、一般的な認可上は被害者がそれを実行できるとしても、アクション束縛の欠陥である。意図や確認が、正規化されたツール名、引数オブジェクト全体、リクエスト元、対象、金額、有効期限、バッチの構成に束縛されているかをレビューする。リトライと再開されたセッションを確認する。承認が、変更された副作用や重複した副作用を認可してはならない。

**ツールスキーマとディスパッチャの不一致**
スキーマが、エイリアス、余分なフィールド、重複キー、型強制、ネストした自由形式オブジェクト、範囲外の値を受け入れ、ディスパッチャやハンドラが別の解釈をする。スキーマ検証、正規化、生成されたバインディング、ハンドラのデフォルトを比較する。値がリソースセレクタやセキュリティ上重要なオプションになる箇所で再度検証する。

**際限のない委任アクションループ**
有限のリクエストが、リクエスト単位の予算、アクション単位の認可、キャンセル、冪等性の制御なしに、繰り返しの支出、送信、変更、外部 API 処理をキューに積める。共有コスト、クォータ、他ユーザー、永続状態への影響を確認する。サービスを枯渇させてテストしない。コードレベルの計算と、ローカルで上限を設けたループを使う。

## MCP とサブエージェントの信頼クラス (subagent_type: `general`)

**サブエージェントと MCP の信頼継承**
委任されたタスクが、必要最小限の権限ではなく、セッション全体、クレデンシャル、メモリ、ケイパビリティを受け取る。各呼び出しに運ばれるプリンシパルとテナント、ケイパビリティの絞り込み、クレデンシャルの audience、委任結果が戻り時に信頼できないものとして扱われるかを確認する。

**MCP サーバーとツールの ID 混同**
呼び出しや結果が、認証済みの接続と未完了のリクエストではなく、攻撃者が影響できるサーバー名、ツール名、リクエスト ID、リソース URI、モデルが選んだエイリアスでルーティングされる。2 つのサーバーが同じツールやリソースの ID を主張できるか、再接続で束縛が変わるか、あるサーバーの応答が別のサーバーの保留中呼び出しを満たせるかを確認する。

**ポリシーとして扱われる MCP のメタデータとスキーマ**
MCP ピアが提供するツール説明、リソースメタデータ、プロンプト、補完ヒント、スキーマが、ポリシーや認可として信頼される。これらのフィールドはモデルを誘導しうるが、ケイパビリティを付与できない。メタデータと矛盾したときにも権威を保つ、決定論的な許可リスト、サーバー ID チェック、ハンドラの認可を見つける。

## 出力と開示の攻撃クラス (subagent_type: `general`)

**安全でない出力レンダリング**
モデル出力が、シンクに必要なエンコーディングとポリシーなしに、実行される HTML、Markdown、テンプレート、URL、コマンドのシンクに到達する。ブラウザでのレンダリングについては、自動読み込みされるリソースと CSP またはサニタイズを `CLIENT-SIDE.md` に従って検証する。リポジトリ外のレンダラの挙動に依存する場合、候補は `needs_validation` とする。

**機密コンテキストの抽出**
組み立てられたコンテキストに、クレデンシャル、他ユーザーのデータ、非公開ソース、それ自体がアクセスを与えるポリシー値が含まれ、ユーザーが影響できる出力がそれを露出する。プロンプト組み立てとデータ取得のコードを読む。データ境界を越えない一般的な指示や振る舞いの開示は指摘ではない。

## 共通の手順 (上記すべてに適用)

- まず 4 つのマップを描く。各実行 ID、各ケイパビリティ、書き込み可能なすべてのコンテキストまたはメモリソース、各出力先である。そのうえで、起点のプリンシパルを終点の権限につなぐ。
- 副作用のあるツールから始め、ディスパッチャ、スキーマ、確認、モデルコンテキスト、検索、取り込みへと逆向きにたどる。永続メモリの読み出しから始め、すべての書き込み元を追跡する。
- 同じアクションについて、直接、キュー、リトライ、再開、バッチ、委任の各経路を比較する。最も強いゲートは、引数が確定した後、かつすべての副作用の前に適用されなければならない。

## 検証ルール (ここでの指摘を報告する前に必ず適用)

1. 越えられた境界と観測可能な結果を明示する。攻撃者、影響を受けるプリンシパルまたは共有リソース、実行 ID、対象、そして認可されていない、または要求されていないアクションや開示である。
2. confused deputy の権限を主張する場合、ツールにリクエスト元とリソースに対する認可がなく、攻撃者が通常の方法で同じアクションを行えないことを証明する。アクション束縛を主張する場合は代わりに、攻撃者が制御するコンテンツが、影響を受けるプリンシパルが意図的に要求も承認もしていないアクションを、そのプリンシパルの権限で起こしたことを証明する。有効な一般的認可は、その意図を立証しない。
3. メモリや検索の主張では、攻撃者が制御する書き込みと、後のプリンシパル間の読み出しまたは特権判断の両方を示す。到達可能な消費者のない共有レコードだけでは足りない。
4. アクション束縛では、意図的なリクエストまたは正規化された承認済みオブジェクトがあればそれを確定し、ハンドラが使うオブジェクトと比較する。有害な実行にまでテストを広げずに、ローカルで観測可能な要求されていないアクション、変更、重複、権限の変化を確認する。スキーマの不一致では、正規化された検証済みオブジェクトとハンドラのオブジェクトを比較する。
5. MCP の ID に関する主張では、認証済みの接続、リクエストの対応付け、ツールの名前空間、実効クレデンシャルを検証する。外部サーバーの ID やデプロイのルーティングが必要なら `needs_validation` とする。
6. `confirmed` の指摘は、完全なソーストレースと意味のある結果がある場合にのみ返す。未解決の具体的な境界事実がある場合は `needs_validation` を返し、それを解決するために必要な、範囲を限ったローカルの確認またはオーナーによる観測を述べる。
