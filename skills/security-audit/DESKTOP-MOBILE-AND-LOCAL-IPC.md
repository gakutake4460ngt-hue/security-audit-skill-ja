# デスクトップ、モバイル、ローカル IPC の調査

#### このファイルを使う場面

対象がデスクトップまたはモバイルアプリ、特権ヘルパー、アップデーター、ローカルデーモン、Webview ホスト、ディープリンクハンドラー、ブラウザのネイティブメッセージングホスト、ローカル IPC のクライアント/サーバーである場合にこのファイルを使う。関係する信頼できないアクターは、ダウンロードされたドキュメント、リモートの Web コンテンツ、別のローカルアプリ、別の OS ユーザー、サンドボックス化されたプロセス、より低い権限のアカウントであり得る。すべてのローカルユーザーを同等に扱わず、その出発点となる能力を明記する。

ブラウザ側の Webview の挙動には `CLIENT-SIDE.md`、ネイティブのメモリとローダーの安全性には `MEMORY-SAFETY-AND-BINARY.md`、アップデートの真正性には `SUPPLY-CHAIN-AND-RELEASE.md` を使う。

## 基本原則 (このドメインのすべてのエージェントプロンプトに含める)

```
- Establish the realistic local or remote-content attacker: another app, another OS user, a sandboxed child, an untrusted document, or a remote origin. Self-harm within the same account and authority is not a boundary violation.
- Paths, process names, bundle/package IDs, and claimed sender fields are not peer authentication. Use OS peer credentials, code identity, capability handles, or protected channel state.
- The native bridge or helper must authorize each operation and final resource after parsing. A trusted UI or broker does not make attacker-influenceable arguments trusted.
- OS sandbox, signing, entitlements, permissions, keychain ACLs, exported-component policy, and prompt behavior are real controls when pinned and visible.
- Use `confirmed` for source evidence plus bounded local/emulator tests. Use `needs_validation` when signing, manifest merge, OS version, device policy, installer ACL, or packaging is required but not observable.
```

## ディープリンク、コールバック、ナビゲーションの攻撃クラス (subagent_type: `general`)

**カスタムスキームとディープリンクの曖昧さ**
別のアプリやページが、現在のセッションと一回限りのコールバックへの束縛なしに、状態を変更する、データをインポートする、認証を完了する、アカウントを選択するルートを呼び出せる。URI の正規化、重複するクエリフィールド、スキーム/ホスト/パスの照合、エクスポートされたアクティビティ/ハンドラーのポリシー、古い/リプレイされたリンクをレビューする。

**アプリとアカウントの引き渡しの取り違え**
OAuth、SSO、マジックリンク、招待、デバイスペアリング、パスワードレス、決済のコールバックが、誤ってインストールされたアプリ、プロファイル、テナント、保留中のトランザクションに戻る。状態を、開始したアプリのアイデンティティ、現在のセッション、アカウント、プロバイダー、操作、有効期限に束縛する。

**ファイルオープンとインテントの権限の取り違え**
関連付けられたファイル、共有インテント、ドラッグ&ドロップの項目、ペーストボード/クリップボードのレコード、通知アクション、ファイルオープンイベントが、コンテンツの種類、該当する場合は送信元の信頼、現在のユーザーの意図、最終的な対象を確認せずに特権操作を引き起こす。

## Webview とネイティブブリッジの攻撃クラス (subagent_type: `general`)

**ナビゲーション元のオリジンとブリッジの取り違え**
リモートまたは攻撃者が制御するフレームが、パッケージ同梱のコンテンツ専用の JavaScript/ネイティブブリッジに到達できる。呼び出し時点で、またすべてのナビゲーション、リダイレクト、サブフレーム作成、ポップアップ、エラー/フォールバックページの後にオリジンを検証する。URL のプレフィックスチェックや初回ロード時のチェックだけでは不十分である。

**広すぎるネイティブブリッジの機能**
Web コンテンツが汎用ブリッジを通じて、任意のファイル、コマンド、IPC メソッド、クレデンシャル、システムアクションを選択できる。メソッドの許可リスト、正規化された引数、ユーザー/テナントの権限、ジェスチャー/確認の要件、戻り値による情報漏洩を確認する。

**Webview のファイルアクセスとユニバーサルアクセス**
ファイルアクセス、ユニバーサルアクセス、混在コンテンツ、デバッグインターフェース、カスタムプロトコルハンドラーによって予期せずオリジンが結合され、リモートコンテンツがアプリのローカルファイル、特権的なカスタムスキーム、内部オリジンを読める。到達可能な保護対象コンテンツがないまま制限的な設定が欠けているだけであれば、ハードニングの扱いである。

## ローカル IPC とエクスポートされたコンポーネントの攻撃クラス (subagent_type: `general`)

**IPC ピア認証の欠落**
Unix ソケット、名前付きパイプ、XPC、Binder、D-Bus、ネイティブメッセージング、RPC、共有メモリ、ループバックのリスナーが、OS のクレデンシャル、コードアイデンティティ、サンドボックストークン、チャネルの所有を確認せずに、より低信頼のピアを受け入れる。チャネルの背後に意味のあるメソッドや情報開示があることを要件とする。

**主張されたプリンシパルとチャネルのアイデンティティ**
認証されたプロセス/チャネルはあるアプリやユーザーに属するのに、リクエストのフィールドが別のユーザー、テナント、プロファイル、機能を選択する。各メソッドとリソースを、呼び出し元が宣言した識別子ではなくピアのクレデンシャルに束縛する。

**エクスポートされたサービス、アクティビティ、レシーバー、プロバイダーの越権**
モバイルのコンポーネントやローカルの自動化エンドポイントが外部から呼び出し可能で、アプリ自身向けの操作を実行する。最終的にマージされたマニフェスト、インテントフィルター、パーミッション/署名レベル、パスの付与、別名をレビューする。パッケージング後のマニフェストの状態が不明な場合は `needs_validation` とする。

**IPC のライフサイクルと対応付けの取り違え**
予測可能なリクエスト ID、再利用されたハンドル、古いチャネル、継承されたディスクリプター、誰でも書き込めるソケットパス、再起動時の挙動によって、あるピアが別のピアの操作に応答、キャンセル、再利用できる。ソケットファイル、ロック、ポート、共有マッピングの作成時のパーミッションとクリーンアップをレビューする。

## 特権ヘルパーとローカルファイルの攻撃クラス (subagent_type: `general`)

**混乱した代理 (confused deputy) としての特権ヘルパー**
低権限の呼び出し元が、操作ごとの認可なしに、特権的なコマンド、ファイル、サービス、ユーザー、システム設定を選択できる。sudo/polkit/UAC/XPC のヘルパールールをレビューし、ヘルパーが正規化された引数を独立して検証することを確かめる。

**インストール、アップデート、修復のパスの信頼**
特権インストーラー/ヘルパーが、認可の後に、より低信頼のアクターが書き込めるマニフェスト、スクリプト、パッケージ、シンボリックリンク、作業ディレクトリ、修復状態を読む。認可を、変更不可能なコンテンツと安全な書き込み先パスに束縛する。

**ローカルファイルの所有権と TOCTOU**
アプリがファイル/パスをチェックした後、特権的な読み書きの最中に起きる置き換え、シンボリックリンク、マウント、大文字小文字/正規化の変化に追従してしまう。ディスクリプター相対の操作を使い、最終的な所有者を検証する。ファイルを開いた後のパースについては `MEMORY-SAFETY-AND-BINARY.md` で扱う。

**クレデンシャルストアとローカルシークレットの境界の不一致**
キーチェーン/キーストアの項目、トークンファイル、バックアップ、ログ、クリップボード、通知のプレビュー、ローカル設定を、より権限の低い別のアプリ/プロファイル/ユーザーが読める。意図した同じ OS アカウントだけが読める平文は、それだけでは脆弱性ではない。より低信頼の読み手とクレデンシャルの権限を明記する。

## アプリケーション状態とデバイスライフサイクルの攻撃クラス (subagent_type: `general`)

**アカウント切り替え、ログアウト、デバイス復元による漏洩**
キャッシュされたデータ、バックグラウンドタスク、ウィジェット、通知、ローカルデータベース、Webview のストレージ、生体認証の承認が、ログアウト/アカウント変更後も残り、後のアカウントの下で現れる。バックアップ/復元と複数プロファイルでの挙動をレビューする。

**保留中のアクションとユーザー在席の取り違え**
通知、ウィジェット、ショートカット、共有シート、生体認証プロンプト、遅延された操作が、表示とは異なるアクションを認可する、有効期限後に実行される、あるいは別プロファイルの保留状態を使う。確認を、正規化されたアクション、リソース、アカウント、現在のフォアグラウンド状態に束縛する。

## 共通の手順 (上記すべてに適用する)

- すべてのプロセス、アプリコンポーネント、ローカルエンドポイント、URI スキーム、ファイル関連付け、Webview のオリジン、ヘルパーを列挙する。OS 上のアイデンティティ、実行時の権限、呼び出し元、呼び出し可能な操作を記録する。
- 最終的なパッケージングの入力を読む。マージされたマニフェスト、エンタイトルメント、インストーラーのルール、ネイティブメッセージングの登録、プロトコルハンドラー、ACL の作成である。ソース上の宣言は下流で上書きされ得る。
- 隔離されたマシン/エミュレーター上で、ダミーのプロファイルと機密でないローカルフィクスチャを使って検証する。他のユーザーのアプリ、クレデンシャル、本番サービスには触れない。

## 検証ルール (ここでの指摘を報告する前に必ず適用する)

1. 攻撃者の出発点となる能力、越えられる OS/アプリのプリンシパル、入口のチャネル、受け入れられる引数や状態、不正な操作または情報開示を明記する。
2. 適用される OS のサンドボックス、ピアクレデンシャル、署名、エンタイトルメント、パーミッション、ユーザー同意、インストーラーの制御を確認する。パッケージング/ランタイムの事実が不明な場合は `needs_validation` とする。
3. Webview ブリッジでは、ナビゲーション/オリジンの制御と特権的なネイティブシンクの両方を引用する。IPC では、ピア認証とリソースごとの認可を引用する。ヘルパーでは、最終的な正規化後の書き込み先を検証する。
4. ローカルテストは範囲を限り、ダミーのコンテンツ/アカウントを使う。境界の結果を証明したら止め、永続化やより広いシステム変更にまで証明を広げない。
5. `confirmed` を返すのは、ソースとローカルの証拠の連鎖が完全な場合だけである。`needs_validation` は、必要となる正確な OS、マニフェスト、署名、ACL、デバイスライフサイクルの事実とともに返す。
