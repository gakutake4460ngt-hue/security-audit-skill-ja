# メモリ安全性、バイナリ、カーネルの調査

#### このファイルを使う場面

対象がメモリ安全でない、または特権のあるコンテキストで信頼できないバイト列を処理する場合にこのファイルを使う。具体的には C/C++/Objective-C、Rust の `unsafe`、FFI、カーネルモジュールとドライバー、パーサーとデコーダー、ネットワークデーモン、ファームウェア、バイナリローダー、言語ランタイム、JIT である。プロトコルの認可と状態機械のロジックには `PROTOCOLS-RPC-AND-MESSAGING.md` を使い、プロセスの完全性、メモリ安全性、ABI 境界、ローダーの挙動にはこのファイルを使う。

Phase 1 から関連するクラスを選び、大きな対象はパーサー、アロケーター/ライフタイム、FFI、並行性、ローダー、ランタイム、特権インターフェースごとに分割する。

## 基本原則 (このドメインのすべてのエージェントプロンプトに含める)

```
- Re-derive every bound and lifetime from attacker-controlled inputs and all callers. Validate against the worst accepted case, not a typical test vector.
- A panic, sanitizer finding, or crash proves a defect only when a realistic untrusted input reaches it. Do not infer memory corruption, code execution, or shared availability impact from a label alone.
- Validate in a local harness with sanitizers, deterministic concurrency tests, existing fuzz targets, and debugger-assisted fault classification. Stop after proving the violated invariant and observable impact; do not develop post-corruption techniques.
- Assembly, JIT code, custom allocators, intra-object accesses, and foreign libraries can escape sanitizer coverage. Identify which relevant instructions are instrumented.
- Classify as `confirmed` only after source evidence and bounded local validation establish the defect and effect. Use `needs_validation` when ABI, allocator, architecture, feature, deployment, or reachability facts remain unknown.
```

## 境界、整数、表現の攻撃クラス (subagent_type: `general`)

**範囲外の読み取りまたは書き込み**
長さ、オフセット、インデックス、終端子が、正しい境界チェックなしに固定長または確保済みのバッファに到達する。プレフィックス、アライメント、パディング、終端子を考慮した後の残り容量を計算し直す。コピー元とコピー先の両方の容量を確認し、宣言された長さを信頼する前に短い入力を読んでいないかを確認する。

**整数のオーバーフロー、アンダーフロー、切り詰め、符号**
アロケーション、コピー、ループ、インデックス、ポインター操作の前にある、攻撃者が制御する算術をレビューする。よく当たるパターンは、`b > a` のときの `a - b`、`count * element_size`、型の最大値付近での加算、符号なしに変換される負の値、32 ビットフィールドに狭められる 64 ビットの長さ、大きなサイズになる `-1` のような番兵値である。後で実際に使われるのがどのチェック済みの表現かを確認する。

**単位とポインター深さの取り違え**
コードがバイト、要素、コードユニット、ページ、ワード、ワイヤ上の単位、あるいはネストしたポインターの要素サイズを混同する。パース、検証、アロケーション、API 境界、コピーの各時点で単位を比較する。アロケーションと同じ誤った単位を使う境界チェックは、やはり誤りである。

**未初期化または部分的に初期化されたデータ**
バッファ、パディング、構造体フィールド、ベクターの容量が、初期化前に返される、比較される、ハッシュされる、シリアライズされる、あるいは信頼境界を越えて渡される。観測可能な消費者と現実的な出力長を要件とする。スタックアロケーションそれ自体は情報漏洩ではない。

## ライフタイム、型、並行性の攻撃クラス (subagent_type: `general`)

**解放後使用 (use-after-free)、古いビュー、二重解放**
コールバック、待ちキュー、タイマー、イテレーター、借用スライス、キャッシュされた生ポインターがまだ使える状態で所有者が解放される。すべてのエラー、キャンセル、クローズ、realloc の経路をレビューする。埋め込まれた通知アンカーについては、すべての解放経路がすべてのオブザーバーを排出 (drain) または切り離さなければならない。

**型の取り違えと不正なダウンキャスト**
タグ、vtable、共用体の判別子、オブジェクト種別、外部ハンドルが、後で読まれる表現とは異なる形でチェックされる。チェックなしの動的キャスト、再利用後に古くなったタグ、検証された要素と消費される要素が異なるシリアライズされた型を探す。違反した不変条件を超えてテストを広げずに、誤った型での読み取りや書き込みをローカルで確認する。

**参照カウントと所有権の競合**
非アトミックな retain/release、チェック後のロックなしの使用、スレッド間で一貫しない所有権によって、アクセス中にオブジェクトが解放または変更され得る。高速経路、エラー、シャットダウン、互換性の経路で、同じロックと所有権のルールが守られているか比較する。

**共有状態の競合と TOCTOU**
並行するパーサーストリーム、グローバルキャッシュ、遅延初期化、シグナルハンドラー、リソースの破棄によって、先に確立した境界、ポリシー、ポインターが無効になり得る。再現可能なローカルのスケジュール、バリア、またはスレッドサニタイザーで競合を検証する。セキュリティ上意味のある状態遷移を伴わない仮想的なインターリーブは `needs_validation` にとどめる。

**ロック順序、デッドロック、スタベーション**
外部から到達可能な操作が一貫しない順序でロックを取得する、あるいはコールバックやブロッキング I/O をまたいでロックを保持する。範囲を限った入力で共有された処理の進行を止められる場合にのみ可用性の問題として報告する。それ以外は並行性の欠陥として修正用に記録する。

## FFI と ABI の攻撃クラス (subagent_type: `general`)

**ポインター/長さと所有権の契約の不一致**
呼び出し側と呼び出される側で、誰がバッファを確保、解放、固定 (pin)、変更するか、ポインターがいつまで有効か、長さがバイトか要素かについて認識が食い違う。すべての `extern`、CGo/JNI/Python/ネイティブバインディング、生成されたラッパーの両側をたどる。null、長さゼロ、エイリアシング、コールバックの保持を確認する。

**レイアウト、アライメント、enum の不一致**
外部コードが、アーキテクチャやビルドフラグによって異なる構造体、ビットフィールド、パックされたレコード、コールバックシグネチャ、整数幅、enum、呼び出し規約を受け取る。`repr`、パッキング、アライメント、エンディアン、ABI 固有の型を検証する。リポジトリ内の宣言の不一致はローカルで確認できる。不透明な外部実装の場合は `needs_validation` とする。

**巻き戻し (unwind)、例外、スレッドアフィニティの違反**
巻き戻しを禁じる ABI を例外やパニックが越える、破棄後にコールバックが実行される、あるいは単一のランタイムスレッドを要求する API が別のスレッドから呼ばれる。エラー変換とキャンセルをレビューする。影響を割り当てる前に、プロセスがアボートするのか状態が破損するのかを確認する。

## バイナリロードとランタイムの攻撃クラス (subagent_type: `general`)

**ライブラリ、プラグイン、実行ファイルの検索順序の信頼**
特権プロセスが、より低信頼のプリンシパルが書き込めるパスからライブラリ、プラグイン、ランタイムイメージ、ヘルパーをロードする、あるいは攻撃者が影響を与えられる作業ディレクトリや環境変数を通じて素の名前を解決する。意図したインストール時の所有者と、各フォールバックおよび互換性の検索パスを比較する。ユーザーが自分のプラグインを自分のプロセスにロードするのは境界侵害ではない。

**成果物のアイデンティティまたは署名の束縛の欠如**
ローダーがあるファイルやメタデータレコードを検証するが、パス解決、ファイルの置き換え、アーキテクチャスライス、埋め込みリソースがチェックに束縛されていないため、別のイメージをマップする。供給経路の真正性は `SUPPLY-CHAIN-AND-RELEASE.md` の範囲である。このクラスはローカルでの検証からマップまでのギャップを扱う。

**不正なバイナリメタデータと再配置の処理**
オフセット、カウント、セクション、再配置、シンボル、バイトコード、デバッグメタデータが、範囲、重複、表現のチェックの前に信頼される。範囲を限ったローカルフィクスチャとサニタイザーでパーサーをテストする。メモリ破損と、不正なファイルが安全に拒否される場合とを区別する。

**JIT と生成コードの一貫性**
バリデーター、インタープリター、オプティマイザー、生成コードの間で、型、境界、副作用、ライフタイムの認識が食い違う。同じローカル入力で最適化ありとなしの経路の差分を取る。プロセスの完全性への影響を確認する。言語仕様の範囲内に収まる出力の差異は指摘にならない。

**アンロード、リロード、破棄の安全性**
生きている関数ポインター、コールバック、ワーカースレッド、データビューが、モジュールのアンロードやランタイムのリセット後も残る。シャットダウンとロード失敗時のクリーンアップを、起動時と同じくらい丁寧にレビューする。

## カーネルと特権インターフェースの攻撃クラス (subagent_type: `general`)

**ユーザーコピーの境界と繰り返し読み取り**
システムコール、ioctl、ドライバー、カーネルパーサーが、ユーザーメモリから信頼する事実を導き出した後、同じ可変アドレスを再び読む。リクエスト全体を一度だけコピーするか、後のコピーを再検証する。また、各ユーザーコピープリミティブでのサイズ、方向、アクセスのチェックも監査する。

**特権オブジェクトのライフサイクルとディスパッチの一貫性**
外部から到達可能なオブジェクトで、retain/release の不均衡、オブザーバーを排出しない破棄、チェックされないセレクター/テーブルのインデックス、ガードを省いた重複する互換性経路がある。各ディスパッチ経路と解放経路を並べて差分を取る。

**認可が不十分な強力なインターフェース**
デバイスノード、管理ソケット、ヘルパー、管理 API が、形式は検証するがリソースに対する呼び出し元の権限を検証しない。実際のインターフェースの所有者と到達可能性を確定する。パーミッションやサンドボックスのポリシーがリポジトリの外にある場合は `needs_validation` とする。

## 共通の手順 (上記すべてに適用する)

- 修正箇所と重複する経路について、同じソースからシンクへの形がないか監査する。ある呼び出し元、アーキテクチャ、プロトコル上の役割、フィーチャーフラグ、互換性経路でのチェックは、その兄弟を守らない。
- すべてのパーサーまたは FFI 境界について表を作る。受け入れる長さ/型、チェック済みの表現、アロケーションの所有者、消費者、スレッド、破棄である。ネイティブの指摘の多くは、この表の中の 1 つの不一致である。
- 既存のコーパスと、ローカルで生成した小さな境界値フィクスチャを使う。サニタイザー/ランタイムの正確な出力と、それを引き起こす入力の性質を保存する。大量のリソース消費と稼働中の対象は避ける。

## 検証ルール (ここでの指摘を報告する前に必ず適用する)

1. 現実的な信頼できない入口と、境界、型、ライフタイム、ABI、並行性、ローダー、権限の不変条件に違反する正確な操作を確定する。
2. 観測可能な影響を分類する。不正な読み取り、不正な書き込み、古いエイリアス、誤ったオブジェクト、未初期化の出力、不正なイメージのロード、デッドロック、安全なプロセス終了のいずれかである。観測した以上に強い影響を主張しない。
3. 影響を再現するのに必要な最小限のローカルハーネス、既存テスト、サニタイザー、ファザーを実行する。障害が起きた操作がサニタイザーでカバーされているかを確認し、アーキテクチャ/ビルド条件を記録する。
4. 並行性では、決定的なスケジュールまたはサニタイザーのトレースを使う。バイナリロードでは、チェックされたアイデンティティとマップされたアイデンティティが異なることを証明し、より低信頼の書き込み者を明記する。
5. `confirmed` の指摘を返すのは、正確な入力、ソーストレース、観測結果がある場合だけである。`needs_validation` は、未解決の具体的な到達可能性、ABI、ビルド、デプロイ、ランタイムの事実について返し、必要な範囲を限ったチェックを明記する。
